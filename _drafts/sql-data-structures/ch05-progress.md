## コントローラーの通読メモ（T3 の結果と合わせて T4 に全件渡す）

1. 「対象の件数ではなく LIMIT の大きさで仕事の重さが決まっています」は言い過ぎ。全 2,000 万件では時間は 2.3 秒に増えている。「使うメモリの量は LIMIT の大きさで決まる。読む量は対象の件数で決まる」に分ける。
2. :::message の「この本ではここまでも、ここから先も」は不正確（ヒープの語はこの章が初出）。「この本ではデータ構造の意味で使います」に。あわせて、PostgreSQL が表の格納先を「ヒープ」と呼ぶことは引用候補ファイルに追記した 11.9 の一文を引用して裏づける。
3. CREATE INDEX（約 5 秒）と、副作用の SQL（約 28 秒）の待ち時間を、実行前に予告する。
4. 比較表の「約2.3秒」は他の行の ms 表記と混在。第4章の 3 回のうち 1 つ（2267.419 ms）か「2,267〜2,533 ms」に。
5. 「目録から1行ぶんの場所を見つけるたびに表のページへ飛んで…500万回近く繰り返した」と、その次の「これは1行ごとに表のページへ飛ぶ動きを500万行ぶん重ねたことに近い動きです」が同内容。一文に。
6. ヒープの条件「親の順位が子以下になる」は「親は子より順位が低い（か同じ）」と読めるように書く。2 枚目の図の矢印「入れ替えて整え直す」が新しい根から子へ向いているのは模型として分かりにくい。「70 が根に上がり、80 が子に入る」の説明を直後の文で補う（図はそのままでよい）。
7. はじめに「副作用は、目録を作れば一方的に得をするわけではないことを教えてくれます」は教える口調。「目録を作れば得ばかりとは限らない」の事実の形に。
