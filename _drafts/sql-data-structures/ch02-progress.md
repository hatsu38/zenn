## コントローラーの通読メモ（T3 の結果と合わせて裁定する。T3 には渡していない）

1. 模型図の最後の矢印「ページ735 → 1行が一致 → 結果」は、一致した本が最後のページにあるように読める。題名 42 の本はページ 0 にある。図を「最後まで読み切ってから結果 1 行を返す」形にするか、末尾近くの本を探す場合の模型だと明記する。
2. LIMIT 1 の節で、末尾近くの出力を示す前に「先頭、真ん中、末尾でそれぞれ読んだページはおよそ2、369、736」と数値を先出ししている。
3. `ctid` を使った先頭ページの件数の SQL に説明がない（中 2 基準）。「先頭ページに入っている行だけを数える書き方」と一言添えるか、割り算だけで示す。
4. 「およそ920倍」の説明がない。1,000 冊のときは 7 ページ分（952 冊）に収まらない端数 48 冊のために 8 ページ目を使うので、ページ数が少し多めになる、と一言あると 1,000 倍でない理由が分かる。
5. はじめに「この本はこれから、友人たちの書誌データを取り込んで」の「この本」は「このサービス」。「件数から行数へ、行数からページ数へ」は件数と行数が同じものを指すので言い換えが要る。
6. 会話「1回の検索でざっと10万冊くらいになりそう」は「本がざっと10万冊くらいになりそう」。
7. 「次の章へ」の「1,000冊だったときの番号検索は6ページ」は第1章の出力（1 回目）の Buffers を指すが、第1章本文では読み飛ばした行なので、「第1章の出力にあった `Buffers: shared hit=6`」と示すと追える。
8. 「律儀に仕事が増える」はやや演出。
