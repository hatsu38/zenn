# 2026-09-26 読了記録に人気の偏りを付ける検証

## 目的

2026-09-25 の販売前レビューで、ランキングの上位20冊がすべて2件で同点になっていると指摘された。旧データは `book_id = (n × 7919) mod 1,000,000 + 1` で割り振っており、どの本も全期間でちょうど2件になる。人気の本ほど多く読まれるように、読了記録へ偏りを付ける。

## 環境

- PostgreSQL 18.6（Docker `postgres:18`、aarch64）。使い捨てのコンテナ `skew-trial` を起動し、その中で実行した。lab のコンテナ（`postgresql-structures-lab-db-1`・`reading-log-lab`）には触れていない。
- 旧データ（DB `journey_old`）と新データ（DB `journey_s08`）を同じコンテナに作り、同じ SQL を同じ順で流した。
- 流した SQL は `review-20260925/` の `reader-selected.sql`・`chapter11-selected.sql`・`ranking-repeat.sql`。旧データ版はそのまま、新データ版はデータ生成の `INSERT` だけを差し替えた（`old-*.sql` と `s08-*.sql`）。
- 並列実行と JIT は無効、work_mem は 4MB（各 SQL の先頭の SET のとおり）。

## 新しい生成式

`generator.sql`。

- 人気の順位 r（1〜1,000,000）を、件数が r^-0.8 に比例する分布から選ぶ。密度が x^-0.8 に比例する分布を [1, 1,000,001) で逆関数法により作り、floor(x) を順位にする。
- 逆関数に入れる u は、黄金比の小数部 `n × 0.618… − floor(n × 0.618…)` で作る。乱数を使わないので、何度実行しても同じデータになる。
- 順位 r を `(r × 386413) mod 1,000,000 + 1` で本の番号へ並べ替え、人気の本を番号全体に散らす（386413 は 2 と 5 で割り切れないので、1〜1,000,000 の並べ替えになる）。
- `finished_at` の式は旧データと同じ。対象週（9/14〜9/21）の記録は 499,998 件のまま。

- 偏りを強くするほど、ANALYZE が標本から推定する `book_id` の種類数が実際より小さくなる。s = 0.9 では、推定の小ささから Nested Loop＋Memoize が選ばれ、第9章で見せたいハッシュ結合が出なくなった。

- 最初の試作（`floor(1,000,000 × u^5)` をそのまま順位にした式）は、1位の本に全体の約6%が集まった。連続分布の 0〜1 の区間がまとめて1位になるためで、[1, M+1) で作る式に直した。

**採用：s = 0.8。** 偏りがはっきりし（対象週の1位は20位の約8倍）、上位20冊に同点がなく、第9章と第12章の計画の形が旧データと変わらない。

## 本文への反映で判断したこと

- **第11章の UPDATE の出力。** 旧版の本文は「第8章の `reading_records_order_idx` がない状態で採取した」出力（records=6 fpi=2 bytes=16786）を載せていた。新しい本文は、本の順に進めた状態（`s08-chapter11-selected.log`、日時の Index あり）の出力に差し替え、この注記を外した。読者が本の順に進めたときと同じ条件になる。
- 参考に、日時の Index を消してから同じ UPDATE を流した（`s08-ch11-wal-no-order-idx.*`）。この DB では本42を一度更新して VACUUM した後だったので、新しい版が同じページに収まり、WAL は records=1 bytes=76 だった。本文の流れとは状態が違うので、本文には使っていない。
- **第12章の基準SQL。** 旧版の本文は Bitmap Heap Scan の出力を載せ、「第11章の後の再測定では Index Only Scan になった」と説明していた。新しいデータで本の順に流すと、第11章より前でも Index Only Scan だった（明示的な VACUUM はないので、データを入れた後の autovacuum が可視性マップを付けたと考えられる）。本文は今回の出力に合わせ、Bitmap からの変化を前提にした説明を直した。
- **第9章の Memoize。** 20件の結合から Memoize が消えたので、説明の段落と図 09-loops の Memoize の段を外した。第10章の「第9章に出ていた Memoize」という言い方も直した。

## 今回は直していない食い違い

- **第9章の64kBの節。** 本文の出力は記録を Seq Scan で読んでいて、本文も「記録を読む方法もSeq Scanへ変わっています」と書いている。今回の再実行では、旧データでも新データでも Index Only Scan だった。データの偏りとは関係がないので、この変更では触れていない。
