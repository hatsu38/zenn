---
title: "付録：実行計画の読み方の早見表"
---

本文で読んだ実行計画の表示を、読み方ごとにまとめます。初めて見る計画を読むときに、ここから引いてください。括弧の中は、詳しく扱った章です。症状から直し方を引くときは、付録「自分の遅いSQLを調べる」の手順4の表A.1を使います。

## 計画を読む順番

1. 字下げのいちばん深い処理から読み始め、親へ向かいます。字下げが一段深い処理が、すぐ上の処理の子です（第6章）。
2. 一つの処理の下に子が二つあるときは、処理の方法で順番が決まります。`Hash Join`は、`Hash`の側でハッシュ表を作り終えてから、もう一方の子のレコードを照合します。`Nested Loop`は、上の子の1件ごとに下の子を実行します（Hash Joinは第6章と第9章、Nested Loopは第9章）。
3. 各段の`actual`の`rows`を追い、どこでレコード数が大きく減るかを見ます。結果の件数が少なくても、途中の段では多くのレコードを扱っていることがあります（第6章、第12章）。
4. 推定の`rows`と`actual`の`rows`が大きく違う段を探します。見積もりがずれると、その上の段の方法の選び方もずれます（第10章）。

## 1行目の読み方

```sql:実行結果
Seq Scan on books  (cost=0.00..19853.00 rows=1 width=30) (actual time=0.036..35.994 rows=1.00 loops=1)
```

表B.1　1行目の表示
| 表示 | 読み方 |
| --- | --- |
| `Seq Scan on books` | 処理の方法と、読む対象（第1章） |
| `cost=0.00..19853.00` | 実行前に見積もった処理量。前は最初の1件を返すまで、後ろはすべて返すまで。ミリ秒ではなく、候補の計画を比べるための値（第1章、第10章） |
| `rows=1`（`cost`の側） | 返すと見積もったレコード数（第1章、第10章） |
| `width=30` | 返す1件のおおよその大きさの見積もり。単位はバイト（第1章） |
| `actual time=0.036..35.994` | 実際にかかった時間（ミリ秒）。前は最初の1件を返すまで、後ろはすべて返し終えるまで。子の処理の時間を含む。クエリ開始からの時刻ではない（第1章、第6章、第7章） |
| `rows=1.00`（`actual`の側） | 実際に親へ返したレコード数（第1章） |
| `loops=1` | この処理を実行した回数（第1章、第9章） |

## loopsが複数のとき

表B.2　loopsが複数のときの値
| 項目 | `loops`が複数のときの値 |
| --- | --- |
| `actual time`、`actual`の`rows` | 1回当たりの平均。`loops`を掛けると全体の量 |
| `Rows Removed by Filter`などの除外したレコード数 | 1回当たりの平均 |
| `Buffers` | 全部の回の合計 |
| `Heap Fetches`、`Index Searches`、`Heap Blocks` | 全部の回の合計 |

どの項目も、親の値は子の値を含みます。親と子の値を足すと、子の分を二重に数えます（第7章、第9章）。

## Buffersの読み方

表B.3　Buffersの表示
| 表示 | 読み方 |
| --- | --- |
| `shared hit` | 共有バッファにあったページを使った回数（第5章） |
| `shared read` | 共有バッファになく、読み込んだ回数。`hit`と足すとページへのアクセス回数（第1章、第5章） |
| `shared dirtied` | この実行中に、新たに変更済みにしたページの数（第11章） |
| `shared written` | 変更済みのページをディスクへ書き出した数。読み取りの回数には足さない（第3章） |
| `temp read`、`temp written` | 作業用メモリからあふれた一時ファイルを読み書きしたブロック数。1ブロックは8kB（第7章） |
| `Planning:`の下の`Buffers` | 計画を作るときに使ったページ。接続して初めての実行で多くなりやすい（第1章） |

大きなテーブルのSeq Scanは、共有バッファの一部だけを使い回す**リングバッファ**で読むことがあります。同じSQLを続けても`read`が残るのはそのためです（第5章）。

## 処理ごとの表示

表B.4　処理ごとの表示
| 表示 | 出る処理 | 読み方 |
| --- | --- | --- |
| `Filter`、`Rows Removed by Filter` | Seq Scanなど | 読んだ後に当てた条件と、それで除いたレコード数（第1章） |
| `Index Cond` | Index Scanなど | Indexで探す範囲を決める条件（第3章） |
| `Recheck Cond`、`Heap Blocks: exact=… lossy=…` | Bitmap Heap Scan | ページ単位の粗い印（lossy）で集めたときに確かめ直す条件と、読んだページの数（第5章） |
| `Heap Fetches` | Index Only Scan | 可視性マップで確かめられず、テーブルのレコードを見に行った回数（第8章、第11章） |
| `Index Searches` | Indexを使う処理 | Indexを上からたどった回数（付録「自分の遅いSQLを調べる」のパターン3） |
| `Sort Method: quicksort` | Sort | 作業用メモリの中で全部を並べた（第7章） |
| `Sort Method: top-N heapsort` | Sort（`LIMIT`付き） | 上位の候補だけを持って選んだ（第8章） |
| `Sort Method: external merge`、`Disk` | Sort | 作業用メモリに収まらず、一時ファイルを使って並べた（第7章） |
| `Buckets`、`Batches`、`Memory Usage` | Hash、HashAggregate | ハッシュ表の箱の数、分けた回数、使ったメモリの最大量（第9章） |
| `Planned Partitions`、`Disk Usage` | HashAggregate | メモリがいっぱいになったら書き出す組の数として実行前に決めておいた数と、一時ファイルに置いた量（第9章、第10章） |
| `WAL: records=… bytes=…` | 変更するSQL（`WAL`オプション付き） | 変更のために生成した記録の数と大きさ（第11章） |

## 最後の行

表B.5　最後の行の表示
| 表示 | 読み方 |
| --- | --- |
| `Planning Time` | 計画を作った時間（第1章） |
| `Execution Time` | 実行にかかった時間。画面に表示し終えるまでの時間ではない（第1章、第7章） |

時間は毎回少し変わります。一度の測定で順位を決めず、何回か交互に測り、レコード数とページへのアクセス回数と合わせて比べます（第5章、第12章）。
