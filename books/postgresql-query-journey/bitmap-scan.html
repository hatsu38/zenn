Bitmap Scanは、条件に合う行の「場所」を先に集めて、同じページの行をまとめて読む方法です。Indexをたどる順番と、テーブルを読む順番を分けるのがポイントです。

行を読むには、ページを開く

テーブルの行は「ページ」という保存単位に入っています。同じページに目的の行がいくつもあれば、まとめて取り出せます。

Indexの順番と、保存場所は別

価格のIndexは価格順。でも、テーブルの行が価格順に保存されているとは限りません。行を一つずつ取りに行くと、ページを行き来することがあります。

Indexで候補の場所を集める

価格のIndexから「ページ1の行1」「ページ4の行2」などの位置を見つけ、ビットマップに印を付けます。この段階では、テーブルから本の全情報を取り出していません。

同じページの候補が一つのメモにまとまり、テーブルをページ順に読む準備ができます。

その後 / Bitmap Heap Scan

候補のあるページをまとめて読む

この図ではページ1 → 4 → 6と進み、それぞれから候補の2行を取り出します。候補のないページ2・3・5・7・8は読みません。

実際には、読んだ行がそのトランザクションから見えるかも確認します。

実行計画では、読む側が上、その材料を作る側が下に表示されます。次は形を理解するための模式例です。実機の出力ではなく、コストや時間も付けていません。

Bitmap Heap Scan on books             ← ② テーブルから行を取り出す
  Recheck Cond: (price BETWEEN 1000 AND 1500)
  → Bitmap Index Scan on books_price_idx ← ① 候補の場所を集める
      Index Cond: (price BETWEEN 1000 AND 1500)

矢印は親子関係を簡略化した表記です。実際の条件表示は price >= 1000 と price <= 1500 などに展開されます。

「全部読む」と「1行ずつ取りに行く」の間にある選択肢

画面が狭いときは、表を横にスクロールできます。

読み方この図でテーブルを訪れる順番得意な場面と負担
Index Scan1 → 4 → 1 → 6 → 4 → 6少数の行をすぐ取り出したいとき。保存場所が散らばっていると、ページを行き来しやすい。
Bitmap Scan1 → 4 → 6候補をページごとにまとめる効果があるとき。ただし、先にビットマップを作る時間とメモリが必要。
Seq Scan1 → 2 → 3 → 4 → 5 → 6 → 7 → 8テーブルの広い範囲を読むとき。Indexを調べずに順に読むが、条件に合わない行も調べる。

Bitmap Scanなら、候補のないページを飛ばし、候補のあるページはまとめて読めます。一方、ほぼ全ページに候補があれば、メモを作る手間に見合わないこともあります。

どれが選ばれるかは、件数だけでは決まりません。行の散らばり方、キャッシュの見積もり、LIMITなども関わります。この小さな例と同じテーブルを実際に作っても、Bitmap Scanが選ばれるとは限りません。

ここまで分かったら、もう少しだけ

「ビットマップ」という専用のIndexを作るの？

この例で用意するのは価格のB-tree Indexです。ビットマップは、クエリの実行中にメモリ上で作る候補位置の情報です。「Bitmap Index Scan」は、Indexを使ってビットマップを作る処理の名前です。

価格順のまま返ってくる？

テーブルをページ順に読むので、元のIndexの価格順は失われます。価格順が必要ならORDER BY priceを指定します。Bitmap Scanを使う計画では、そのためのSortが別途必要になります。そもそも、ORDER BYのないSQLに結果の順番の保証はありません。

複数のIndexの候補も組み合わせられる

価格と著者にそれぞれIndexがあれば、候補位置の集合を組み合わせる方法もあります。BitmapAndは両方に共通する候補、BitmapOrはどちらかにある候補をまとめます。使えるIndexが複数あっても、必ずこの方法を選ぶわけではありません。

Recheck Condは、何を確かめる条件？

Indexから得た候補を、テーブルの行で再確認するときの条件です。たとえばメモリが足りず「行の場所」から「候補のあるページ」へと記録を粗くした場合、そのページ内の行を調べ直します。この粗い記録をlossyと呼びます。上の図は、行の場所まで記録できる場合だけを扱っています。

Recheck Condが表示されているだけで、lossyになったとは判断できません。実測のHeap Blocks: exact=… lossy=…やRows Removed by Index Recheckを確認します。

読み終えたら、図でIndex ScanとBitmap Scanを切り替えてみてください。同じ6行を返しても、テーブルを訪れる順番が変わります。
